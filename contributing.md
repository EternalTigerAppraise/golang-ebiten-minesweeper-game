<h2>🧨 The Classic. Rebuilt in Go.</h2>

<p><strong>Golang Ebiten Minesweeper</strong> is a complete, modern reimagining of the world's most beloved logic puzzle — written from scratch in <strong>Go</strong> and rendered with the <strong>Ebiten 2D game engine</strong>. No frameworks, no bloat, no legacy code. Just clean, readable Go that runs natively on Windows, macOS, Linux, and even in the browser via WebAssembly. It's the same grid. The same numbers. The same sinking feeling when you click a mine. But now it's <strong>fast, beautiful, and open source</strong>.</p>

<blockquote>💡 <strong>Why rebuild Minesweeper?</strong> Because it's the perfect project for learning game development, engine architecture, and clean Go design — and because everyone deserves a version that actually looks good in 2026.</blockquote>

<h2>🚀 Quick Start</h2>

<blockquote><strong>Three commands. Under two minutes. No installers.</strong></blockquote>

<h3>1️⃣ Clone the repository</h3>

<pre><code>git clone https://github.com/yourname/golang-ebiten-minesweeper.git
cd golang-ebiten-minesweeper
</code></pre>

<h3>2️⃣ Run it with Go</h3>

<pre><code>go run .
</code></pre>

<p>That's it. Ebiten downloads its native dependencies automatically on first run.</p>

<h3>3️⃣ Build a standalone binary (optional)</h3>

<pre><code>go build -o minesweeper .
</code></pre>

<p>You'll get a single executable — no runtime, no dependencies.</p>

<h2>⚙️ How It Works</h2>

<table align="center" width="100%" style="border-collapse: collapse;">
<tr style="border-bottom: 2px solid #7B2CBF;">
<th align="left" style="padding: 10px;">Layer</th>
<th align="left" style="padding: 10px;">Responsibility</th>
<th align="left" style="padding: 10px;">Tech</th>
</tr>
<tr><td style="padding: 8px;">🧠 <strong>Game Logic</strong></td><td style="padding: 8px;">Board generation, mine placement, flood fill, win/lose detection</td><td style="padding: 8px;">Pure Go (no rendering)</td></tr>
<tr><td style="padding: 8px;">🎨 <strong>Renderer</strong></td><td style="padding: 8px;">Sprite drawing, animations, tile state visuals</td><td style="padding: 8px;">Ebiten <code>ebiten.Image</code></td></tr>
<tr><td style="padding: 8px;">🎮 <strong>Input Handler</strong></td><td style="padding: 8px;">Mouse and keyboard mapping</td><td style="padding: 8px;">Ebiten input API</td></tr>
<tr><td style="padding: 8px;">⏱️ <strong>Timer & State</strong></td><td style="padding: 8px;">Elapsed time, difficulty, best scores</td><td style="padding: 8px;">Standard Go structs</td></tr>
</table>

<br/>

<p>The codebase follows a strict <strong>separate-concerns</strong> pattern: the game logic package has <strong>no imports from Ebiten</strong>, making it fully testable and reusable in any Go project — CLI, server, or another engine.</p>

<h2>❓ Frequently Asked Questions</h2>

<details>
<summary><b>Can I play it in the browser?</b></summary>
<p>Yes! The project builds to <strong>WebAssembly</strong> with <code>GOOS=js GOARCH=wasm go build</code>. A pre-built demo is linked at the top of this README. Performance in the browser is nearly identical to native.</p>
</details>

<details>
<summary><b>Does it support custom board sizes?</b></summary>
<p>Custom board sizes are on the <strong>roadmap for version 2.0</strong>. For now, you can modify the constants in <code>internal/difficulty</code> and rebuild — the game logic is fully parameterized.</p>
</details>

<details>
<summary><b>Why Go + Ebiten instead of a JavaScript engine?</b></summary>
<p>Go gives us <strong>real concurrency, a single-binary deployment, and rock-solid performance</strong>. Ebiten is the most mature 2D engine in the Go ecosystem — it's battle-tested by thousands of indie games.</p>
</details>

<details>
<summary><b>Can I use this as a learning project?</b></summary>
<p>Absolutely. The codebase is intentionally small and heavily commented. The <code>internal/game</code> package is a perfect reference for <strong>board generation, flood fill algorithms, and clean state machines</strong>.</p>
</details>

<details>
<summary><b>How do I report a bug?</b></summary>
<p>Open an issue on the GitHub repository with your <strong>OS</strong>, <strong>Go version</strong>, and a <strong>screenshot</strong> of the problem. Include the exact steps to reproduce it — that speeds up the fix dramatically.</p>
</details>
